Perfiles por Agente en REASP

Guía para asignar ModeProfiles distintos al Ryou Orchestrator y al Ryou EFI Planner.

Versión 1.0 · 2026-07-10 · REASP modeprofile-ryou-provider-suite

1. ¿Qué hace esta funcionalidad?

Por defecto, REASP/RASS usa un único default_modeprofile para resolver los modelos de todos los agentes. Con la nueva sección agent_modeprofiles en .opencode/reasp.config.json puedes asignar un ModeProfile distinto a cada agente principal:

  • ryou-orchestrator → perfil para el flujo de implementación.
  • ryou-efi-planner → perfil para el flujo de planificación REFI.
Beneficio: puedes usar modelos baratos y rápidos en el Orchestrator (OpenCode Go) y modelos más potentes en el Planner (Kimi o Minimax), o viceversa.

2. Estado por defecto

Después de la implementación, ambos agentes usan ryougo:

{
  "default_modeprofile": "ryougo",
  "agent_modeprofiles": {
    "ryou-orchestrator": "ryougo",
    "ryou-efi-planner": "ryougo"
  }
}

El comportamiento es idéntico al de versiones anteriores: todo apunta a ryougo.

3. Cambiar el perfil de un agente (paso a paso)

Desde la TUI de OpenCode ejecuta el comando del plugin (/sdd) y selecciona la opción "Assign ModeProfile to Ryou agent". Verás dos secciones:

  • Primary agents: ryou-orchestrator y ryou-efi-planner.
  • Subagents: planner, builder, architect, reviewer, debugger, documentation.

1 Elegir agente

Selecciona el agente al que quieres asignar un perfil. Cada opción muestra el perfil actualmente asignado.

2 Elegir perfil

La lista muestra todos los ModeProfiles disponibles. Cada opción indica el modelo que el agente recibirá al seleccionarlo (preview). El perfil actual aparece marcado con ✓ (current).

3 Confirmar

Al confirmar, el sistema:

  1. Actualiza agent_modeprofiles[<agente>] en .opencode/reasp.config.json.
  2. Llama a refreshAllAgentModels() para escribir el modelo en ~/.config/opencode/opencode.json.
  3. Muestra un toast con el modelo resultante.

4 Verificar

Comprueba que cada agente tiene el modelo correcto:

node -e "const c = require(process.env.USERPROFILE + '/.config/opencode/opencode.json'); \
console.log('orchestrator:', c.agent['ryou-orchestrator'].model); \
console.log('planner:', c.agent['ryou-efi-planner'].model);"

Salida esperada:

orchestrator: minimax-coding-plan/MiniMax-M3
planner: kimi-for-coding/k2p7
Listo. Cada agente ahora usa un perfil independiente del otro.

4. Reglas de resolución

Agente Fuente del perfil Fase del perfil usada
ryou-orchestrator agent_modeprofiles["ryou-orchestrator"] o default_modeprofile orchestrator.primary
ryou-efi-planner agent_modeprofiles["ryou-efi-planner"] o default_modeprofile orchestrator.primary
planner default_modeprofile propose.primary
builder default_modeprofile apply.primary
architect default_modeprofile design.primary
reviewer / debugger default_modeprofile verify.primary
documentation default_modeprofile archive.primary
Desde la TUI: la opción "Assign ModeProfile to Ryou agent" lista los dos agentes principales más todos los subagentes (planner, builder, architect, reviewer, debugger, documentation). Puedes asignar perfil a cualquiera de ellos; los que no estén en agent_modeprofiles usan default_modeprofile.

5. Combinaciones típicas

A. Todo OpenCode Go (default)

"agent_modeprofiles": {
  "ryou-orchestrator": "ryougo",
  "ryou-efi-planner": "ryougo"
}

B. Planner con Kimi, Orchestrator OpenCode Go

"agent_modeprofiles": {
  "ryou-orchestrator": "ryougo",
  "ryou-efi-planner": "ryoukimi"
}

C. Todo Minimax

"agent_modeprofiles": {
  "ryou-orchestrator": "ryouminimax",
  "ryou-efi-planner": "ryouminimax"
}

D. Mixer: Planner Kimi, Orchestrator Minimax

"agent_modeprofiles": {
  "ryou-orchestrator": "ryouminimax",
  "ryou-efi-planner": "ryoukimi"
}

6. Validación

Después de cualquier cambio, ejecuta:

node scripts/rass-sync-validator.js

Debe terminar con:

✅ Profile / runtime / opencode.json are consistent.
✅ Repo and global sdd-profiles are in sync.
All checks passed.

Y también los tests automáticos:

node scripts/test-e2e-tool.mjs
node scripts/test-provider-support.mjs

7. Errores frecuentes

Síntoma Causa probable Solución
El modelo del agente no cambia. No ejecutaste sync-reasp push ni rass_setup validate. Ejecuta uno de los dos comandos.
"ryouminimax" not found El perfil no existe en .opencode/sdd-profiles/. Verifica que el archivo ryouminimax.json exista y sea válido.
Todos los agentes vuelven a ryougo. agent_modeprofiles no tiene la clave para ese agente. Agrega el agente a agent_modeprofiles.

8. Reinicio de OpenCode

Importante: los cambios en ~/.config/opencode/opencode.json solo se cargan cuando OpenCode arranca. Después de modificar perfiles, cierra y vuelve a abrir OpenCode para que la nueva configuración tome efecto.

9. Asignar perfiles durante la instalación (reasp-cli)

El instalador REASP también puede asignar perfiles por agente en el momento de instalar. Útil cuando configuras un equipo nuevo.

Modo interactivo

Durante reasp install se te preguntará:

  1. Default ModeProfile.
  2. Default workflow agent.
  3. ModeProfile para Ryou Orchestrator.
  4. ModeProfile para Ryou EFI Planner.

Modo no interactivo (flags)

reasp install \
  --modeprofile ryougo \
  --workflow ryou-orchestrator \
  --agent-profile-orchestrator ryouminimax \
  --agent-profile-planner ryoukimi
FlagDescripción
--modeprofile <id>ModoProfile default del sistema.
--agent-profile-orchestrator <id>ModoProfile para ryou-orchestrator.
--agent-profile-planner <id>ModoProfile para ryou-efi-planner.

10. Persistencia: dónde se guarda

El sistema escribe en dos lugares, en este orden:

  1. Global ~/.config/opencode/reasp.config.json — fuente de verdad que OpenCode lee al arrancar.
  2. Repo .opencode/reasp.config.json — espejo para distribución.

Tras cualquier cambio, ejecuta node scripts/sync-reasp.js push para mantener el repo sincronizado si editas a mano el JSON global.
