Problema reportado

El usuario agregó el soporte de proveedores en REASP (sesión 3) y reinstaló globalmente con npm install -g reasp-cli-1.0.0.tgz, luego corrió reasp install en sus agentes. Después de la reinstalación, las funciones nuevas no aparecían: el tool sdd_mode_profile no aceptaba el argumento provider, y los archivos en ~/.config/opencode/ seguían siendo la versión antigua.

Diagnóstico

El código en el repo REASP/.opencode/ tenía el soporte de proveedores correctamente implementado (DEFAULT_PROVIDERS, discoverProviders, validación, etc.). Los tests pasaban. El problema era de distribución y de PATH:

  1. Tarball desactualizado: reasp-cli-1.0.0.tgz se había generado el 08/07 antes de que se terminaran los cambios de proveedores el 09/07. El .tgz no contenía DEFAULT_PROVIDERS ni discoverProviders.
  2. Tres instalaciones simultáneas en el sistema:
    • C:\Program Files\REASP\ — instalación antigua con prioridad en el PATH (porque C:\Program Files\ está antes que %APPDATA%\npm). Cuando el usuario ejecutaba reasp, se llamaba a C:\Program Files\REASP\reasp.ps1, que ejecutaba la versión antigua.
    • C:\Users\kevin\AppData\Roaming\npm\node_modules\reasp-cli — instalación global correcta de npm, pero sin prioridad en el PATH.
    • C:\Users\kevin\KeorSoft\Development\AITools\REASP — repositorio de desarrollo, fuente de verdad.
  3. Hash mismatch: después de hacer sync-reasp.js push desde el repo, ~/.config/opencode/rass-core.js quedaba con el hash nuevo (43C6…). Pero al ejecutar reasp install, el archivo volvía al hash antiguo (E29C…). El culpable era la instalación antigua en C:\Program Files\REASP\ que sobrescribía los archivos del agente con la versión vieja.

Solución aplicada

Endurecimiento adicional aplicado en el código

  • package.json y installer/lib/constants.js suben a 1.0.1 para que reasp --version evidencie la actualización real.
  • Nuevo installer/scripts/postinstall.js: detecta si Windows resuelve reasp hacia una instalación vieja antes del shim npm, intenta actualizar la instalación standalone si tiene permisos, y si no, muestra una advertencia accionable.
  • El adapter de OpenCode ahora reemplaza directorios/archivos REASP-managed antes de copiarlos, evitando archivos obsoletos que ya no existan en el repo.
  • Los agentes REASP-managed en opencode.json se reemplazan completos en cada reinstalación, no solo el campo model. Así se actualizan prompts, permisos, steps y futuros cambios de schema.
  • model y small_model raíz ahora se re-sincronizan con el ModeProfile en cada instalación.
  • Nuevo scripts/check-syntax.js para que npm test sea cross-platform; los globs anteriores fallaban en Windows PowerShell/CMD.
1
Regenerar el tarball con los archivos actualizados: 
npm pack
Después de este paso el reasp-cli-1.0.0.tgz contiene DEFAULT_PROVIDERS, discoverProviders, validación, y todos los cambios del soporte de proveedores (24 kB plugin.js, 38 kB rass-core.js, 56 kB tui.js).
2
Sincronizar el agente OpenCode con la versión del repo: 
node scripts/sync-reasp.js push
Copia .opencode/ → ~/.config/opencode/ y refresca el runtime desde el ModeProfile activo.
3
Reinstalar REASP globalmente desde el nuevo tarball: 
npm uninstall -g reasp-cli
npm install -g reasp-cli-1.0.0.tgz
Ahora la instalación global de npm coincide con el repo.
4
Identificar y documentar la instalación duplicada. El agente OpenCode (~/.config/opencode/) ya tenía los archivos correctos. La instalación de C:\Program Files\REASP\ sigue siendo la versión antigua y necesita privilegios de administrador para actualizarse — se documentó en la guía y en el troubleshooting.

robocopy "C:\Users\kevin\KeorSoft\Development\AITools\REASP" `

# Opción B — eliminarla para que solo quede la de npm
