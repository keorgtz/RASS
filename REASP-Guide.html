✦ Qué es REASP

REASP une dos sistemas en una sola herramienta:

  • RASS (Ryou Adaptive SDD System) — orquesta tu trabajo con agentes especializados y ModeProfiles adaptativos con soporte multi-proveedor (OpenCode Go, Anthropic, OpenAI, Google).
  • REFI (Ryou Enterprise Feature Implementation) — genera packets de planificación empresarial antes de escribir código.

REASP también es un Backup Manager: guarda snapshots completos de la configuración de cada agente para que puedas recuperarte si algo sale mal.

◈ Requisitos

Node.js
Versión 18 o superior

REASP está construido como un paquete npm en ES modules.

npm
Incluido con Node.js

Necesario para instalar el comando reasp globalmente.

Agentes de IA
OpenCode, Claude Code, Codex, Gemini CLI o Antigravity CLI

REASP detecta automáticamente los que tengas instalados.

➤ Instalación

Paso 1: Clonar o ubicar el repositorio

git clone https://github.com/kevinkeor/RASS.git
cd RASS

Paso 2: Instalar REASP como herramienta global

npm install -g .

Esto registra el comando reasp en tu sistema.

Paso 3: Verificar la instalación

reasp --version
# Debe mostrar: 1.0.0

reasp detect
# Muestra los agentes de IA detectados en tu máquina
💡 Si reasp no se encuentra

Reinicia tu terminal. Si el problema persiste, verifica que el directorio de binarios globales de npm esté en tu PATH:

npm bin -g

◈ Soporte de Proveedores

Desde la versión 1.0.0, RASS permite configurar explícitamente el proveedor de modelo al crear o editar un ModeProfile. Esto resuelve tres problemas reales:

  • Validación previa: RASS verifica que el modelo realmente pertenezca al proveedor que elegiste antes de guardar.
  • Mezcla de proveedores: un mismo ModeProfile puede usar modelos de opencode-go, anthropic, openai o google en distintas fases.
  • Modelos custom: puedes escribir manualmente un string provider/model aunque tu modelo aún no aparezca en el catálogo.

Argumento provider en el tool sdd_mode_profile

El tool que invoca el agente también acepta un argumento provider opcional. Si lo pasas junto con primary, RASS valida que el modelo pertenezca al proveedor:

// Caso correcto: el modelo pertenece al proveedor
sdd_mode_profile(
  action="create",
  name="custom-mixed",
  phases="orchestrator,apply,verify",
  primary="opencode-go/glm-5.1",
  provider="opencode-go",
  effort="medium"
)

// Caso incorrecto: el modelo no pertenece al proveedor
sdd_mode_profile(
  action="create",
  name="bad",
  phases="apply",
  primary="anthropic/claude-sonnet-4-5",
  provider="opencode-go"
)
// → Provider Mismatch: 'anthropic/claude-sonnet-4-5' does not belong to 'opencode-go'

Si solo pasas provider (sin primary), RASS elige automáticamente el primer modelo de ese proveedor. Si omites ambos, RASS usa el default opencode-go/glm-5.1.

Modelos custom (no listados en el catálogo)

Si tu modelo aún no aparece en el catálogo del proveedor (por ejemplo opencode-go/experimental-v1), RASS lo acepta como válido y muestra una advertencia en el output del tool. El modo custom es un first-class citizen: los strings provider/model se almacenan tal cual en disco. 

+ Custom model (provider/model)
  → Enter a "opencode-go/<model>" string manually
  e.g., opencode-go/experimental-v1
💡 Compatibilidad

El formato en disco provider/model no cambió. Los ModeProfiles existentes siguen funcionando sin tocar nada. El argumento provider es estrictamente opcional: si no lo pasas, RASS se comporta exactamente como antes.

◐ Sistema de Snapshots

Los snapshots son copias completas del directorio de configuración de un agente. Se almacenan en: 

~/.reasp/snapshots/<agente>/<timestamp>-<nombre>/

Comandos esenciales

Crear snapshot

reasp snapshot create --agent claude-code --name clean --yes

Listar snapshots

reasp snapshot list
reasp snapshot list --agent claude-code --json

Restaurar snapshot

reasp snapshot restore --agent claude-code --name clean --yes

Antes de restaurar, REASP crea automáticamente un auto-restore-backup-<timestamp> del estado actual.

Eliminar snapshots

reasp snapshot delete --agent claude-code --name clean --yes
reasp snapshot purge --agent claude-code --keep 3 --yes
🛡️ Consejo de seguridad

Crea siempre un snapshot antes de instalar, desinstalar o actualizar REASP en un agente. El instalador te lo ofrecerá automáticamente, pero también puedes hacerlo manualmente.

▲ Flujo de trabajo típico

Con REASP instalado en OpenCode, este es el ciclo recomendado para una feature empresarial:

1
Planificación con Ryou EFI Planner
Activa el planner vía /reasp-setup y pide que diseñe el módulo. Se generará un packet REFI en .refi/modules/<feature>/.
2
Cambio a Ryou Orchestrator
Cuando el packet esté listo, cambia al orchestrator con /reasp-setup para ejecutar la implementación.
3
Implementación adaptativa
El orquestador elige el ModeProfile adecuado (Fast, Architecture, UI, Debug, etc.) y delega a subagentes especializados.
4
Verificación y resumen
Al terminar, se actualiza verification.md y se genera el resumen diario en AI/Summarys/summary-YYYY-MM-DD.html.

✗ Solución de problemas

reasp no se reconoce

  • Reinicia la terminal.
  • Verifica que el directorio de npm bin -g esté en tu PATH.
  • Como alternativa, usa el wrapper: scripts\reasp.cmd (Windows) o scripts/reasp (Unix).

Un install no funcionó y el agente quedó dañado

reasp snapshot list --agent <agente>
reasp snapshot restore --agent <agente> --name <tu-snapshot-previo> --yes

No se detecta un agente

  • Asegúrate de que el CLI del agente esté en tu PATH.
  • Puedes forzar la instalación con --force:
reasp install --agents claude-code --force

Snapshot restore falló

Busca el auto-restore-backup-<timestamp> generado antes del restore y restáuralo:

reasp snapshot restore --agent <agente> --name auto-restore-backup-<timestamp> --yes

Instalé una nueva versión pero reasp sigue siendo la antigua

Síntomas típicos:

  • Acabas de clonar el repo, ejecutas npm install -g reasp-cli-1.0.0.tgz y los archivos en ~/.config/opencode/ siguen siendo la versión anterior.
  • reasp install parece no hacer nada o devuelve errores de funciones inexistentes.

El problema casi siempre es que el PATH está apuntando a una instalación duplicada de REASP. Verifica qué reasp se está ejecutando realmente:

where.exe reasp          # Windows
which -a reasp          # macOS / Linux
Get-Command reasp      # PowerShell

Si el primer resultado no es el de npm, hay otra instalación con prioridad. Las ubicaciones comunes son:

  • C:\Program Files\REASP\reasp.ps1 (Windows, instalación manual)
  • C:\Users\<user>\AppData\Roaming\npm\reasp.cmd (instalación correcta de npm)
  • /usr/local/bin/reasp (Linux/macOS)

Solución: o bien borra/renombra la instalación antigua, o bien copia los archivos nuevos del repo a la carpeta con prioridad en el PATH. Por ejemplo, en Windows con PowerShell como administrador:

robocopy ".\REASP" "C:\Program Files\REASP" /MIR /XD .git node_modules installer\node_modules

Después regenera el tarball y reinstala globalmente desde npm para mantener una sola fuente de verdad:

npm pack
npm install -g reasp-cli-1.0.0.tgz

El soporte de proveedores no aparece en el TUI

Asegúrate de que el archivo ~/.config/opencode/rass-core.js contiene las funciones nuevas:

node -e "import('file:///C:/Users/<user>/.config/opencode/rass-core.js').then(m => console.log(typeof m.discoverProviders, typeof m.validateModelInProvider))"
# Debe imprimir: function function

Si imprime undefined undefined, tu instalación está desactualizada. Repite los pasos de la sección anterior.

El tool reporta "ModeProfile 'X' not found" pero el perfil existe

El archivo ~/.config/opencode/runtime/current-modeprofile.json apunta a un perfil que ya fue eliminado. Corrige el valor:

node -e "import('node:fs').then(fs => fs.writeFileSync(process.env.USERPROFILE + '/.config/opencode/runtime/current-modeprofile.json', JSON.stringify({modeprofile:'ryougo'}, null, 2)))"

◇ Desinstalación

Para eliminar REASP de un agente específico:

reasp uninstall --agents opencode,claude-code --yes

Para eliminar el comando global:

npm uninstall -g reasp-cli
💡 Nota

Desinstalar REASP no borra tus snapshots. Para limpiarlos, usa reasp snapshot purge --all-agents --keep 0 --yes.
