REASP
Ryou Enterprise Adaptive SDD Protocol
La fusión definitiva de RASS (Orquestación Adaptativa) y REFI (Planeación Empresarial) para OpenCode.

1 Instalación

Para instalar REASP en tu sistema, clona el repositorio de RASS y ejecuta el instalador visual.

git clone https://github.com/kevinkeor/RASS.git
cd RASS/installer
npm install
node index.js

En el menú interactivo, selecciona "Install globally" para habilitar REASP en todos tus proyectos de OpenCode.

2 Configuración

Una vez instalado, puedes gestionar el workflow activo directamente desde OpenCode usando comandos slash:

  • /reasp-setup: Centro de mando para cambiar el agente activo.
  • /reasp: Alias rápido para el setup.
  • /sdd: Cambia el ModeProfile (Fast, Architecture, UI, etc.).

Para empezar una nueva feature, asegúrate de tener activo el Ryou EFI Planner.

3 Herramientas

REASP despliega un ecosistema completo:

  • Ryou EFI Planner: Especialista en arquitectura y packets REFI.
  • Ryou Orchestrator: Especialista en ejecución y despliegue.
  • RASS Core: Motor de routing de modelos y fases.
  • REFI Toolkit: Reglas globales y plantillas de blueprint.

Ejemplo Práctico: API Web con C#

Implementemos un "Módulo de Gestión de Inventarios" desde cero.

Fase 1: Planeación (Ryou EFI Planner)
Generación del Packet REFI

Activa el agente EFI vía /reasp-setup → Ryou EFI Planner.

Usuario "Necesito implementar un módulo de Gestión de Inventarios para una API Web en C# (.NET 9). Incluye control de stock, alertas de stock bajo y reportes de movimiento."

El agente no escribirá código aún. Creará la estructura .refi/modules/inventario/ con:

  • master-blueprint.md: Definición de endpoints, modelos de datos y riesgos.
  • domain-shards/: Fragmentos de trabajo (01-Persistencia, 02-Servicios, 03-API).
  • orchestration-map.md: Orden exacto de ejecución y puertas de verificación.
Fase 2: Implementación (Ryou Orchestrator)
Ejecución Incremental

Ahora, cambia el workflow vía /reasp-setup → Ryou Orchestrator.

Usuario "Basándote en el packet de Inventario, implementa el shard 01 (Persistencia y Base de Datos)."

El Orquestador ejecutará el flujo adaptativo (ej. Architecture Mode):

  • Explore: Analiza la base de datos actual.
  • Apply: Crea las entidades de EF Core y la migración.
  • Verify: Valida que la migración se aplique correctamente.
Fase 3: Cierre y Verificación
Aseguramiento de Calidad

Repite el proceso para los shards 02 y 03. Al finalizar:

Usuario "Genera el reporte de verificación final para el módulo de Inventario y actualiza el resumen diario."

El sistema cerrará el ciclo actualizando verification.md y creando el resumen visual en AI/Summarys/summary-YYYY-MM-DD.html.
